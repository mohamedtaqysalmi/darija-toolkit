darija-toolkit

I built this because chatbot pipelines choke on Moroccan chat text that mixes Arabizi, Arabic script and French. The first release turns Arabizi into Arabic script with ranked alternatives, then detects and normalizes the noisy bits.

    What problem it solves

    Recruiters and clients in Morocco type Darija in Latin letters with digits for ع ح ق خ. Most NLP stacks assume either clean MSA or French. This package is a small, testable pre-processor for that middle ground.

    Works now

    • Arabizi → Arabic script with alternatives + scores
    • Heuristic detect: Arabizi / Darija Arabic / MSA / French / mixed
    • Chat normalizer (elongations, variants, punct noise)
    • FastAPI /transliterate /detect /normalize
    • Typer CLI

    Not done / partial

    • Accuracy is only measured on the fixture set (unreviewed)
    • No ML model; short vowels are guessed
    • Detector is keyword/script heuristics, not trained
    • Not published to PyPI yet

    Quickstart

    pip install -e ".[dev]"
darija-toolkit transliterate "salam labas 3lik"
uvicorn darija_toolkit.api:app --reload

    How it works

    Digraphs and chat digits first, then position-aware vowels, then a tiny lexicon for words the letter rules butcher. Alternatives come from swapping one option slot at a time. 

    Arabizi token
   │
   ├─ lexicon hit? ──► fixed Arabic spelling
   │
   ├─ collapse elongations (mzyaaaan → mzyaan)
   ├─ match digraphs / digits (ch, kh, 3, 7, 9…)
   ├─ pick vowel options by position
   └─ expand alternatives from non-default slots
         │
         ▼
   best Arabic + ranked alternatives

    How I built it

    Rules as data, not a model

    I needed something that runs offline, ships in a small package, and can be ported to JS for this page. A fine-tuned model would score better on free text and worse on install size, cold start and explainability in an interview.

    Shared fixtures between Python and JS

    The playground loads rules.json exported from the same tables the package uses. The failure table is the fixture file. If they drift, CI and this page disagree in public.

    Honest xfail instead of silent wrong “passes”

    Cases the rules get wrong stay in the suite as strict xfails. That keeps coverage of the hard spots without lying that they pass.

    Limitations

    • Fixtures are drafted and not native-speaker reviewed yet.
    • Final ـة vs ا, emphatics, and French loans are frequent miss points.
    • Detector will mis-label short mixed messages; treat scores as relative weights.
    • No PyPI release until I say so in the repo.

    Roadmap lives in GitHub issues.
